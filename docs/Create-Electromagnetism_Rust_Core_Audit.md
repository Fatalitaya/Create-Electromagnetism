# Create-Electromagnetism：代码质量与 Rust 内核审查报告

> 审查范围：Java/Rust 总体架构、Rust `em-core`
> 数值内核、协议与跨语言边界。\
> 审查方式：汇总前两轮源码静态审查记录。\
> 报告性质：工程问题清单与修复建议，不代表完整构建或运行测试报告。

## 1. 执行摘要

项目已形成 Java 世界集成层、JNI/协议层与 Rust
模拟内核的分层。模拟任务调度、revision
管理、候选状态与已接受状态分离、失败回滚及世界副作用确认等设计值得保留。

目前主要风险不是整体架构需要推翻，而是**物理模型、数值算法、容差策略与世界状态提交之间尚未形成足够严格且可验证的一致性契约**。

前两轮审查中最值得优先处理的事项：

1.  AC 求解器对时变源识别不完整，Audio、Impulse 可能绕过拒绝检查。
2.  Newton 修正量容差通过未知量下标推断单位，无法正确处理温升、V²
    等内部未知量。
3.  稀疏求解器的尺度处理和主元判据较简单，病态矩阵边界需要验证。
4.  瞬态推进、相位管理和保护事件定位需要加强边界测试。
5.  Java 设备适配范围与 Rust 内核实际能力需要逐项对应。
6.  上传包缺少完整 workspace/Gradle
    配置，无法据此复现完整构建和发布流程。

**总体建议：保留现有架构，先修复确定问题，再建立数值性质测试，最后扩展设备能力。**

## 4. 已发现的核心问题

### 4.1 AC 求解器对时变源识别不完整

**优先级：P1**\
**位置：** `native/crates/em-core/src/solver/ac.rs`，前轮记录指向第
33--48 行附近。

当前 AC 分析通过 `source_clock()`
判断是否存在时变源。前轮检查发现，该判定覆盖部分时钟源，但
Audio、Impulse 模型具有显式时间依赖性，却未被该检查覆盖。

可能后果：

1.  电路包含 Audio 或 Impulse。
2.  `source_clock()` 返回 `None`。
3.  AC 分析继续计算 DC operating point。
4.  时间相关输入可能被固定在 `t=0` 取值。
5.  求解器将其作为静态偏置条件处理。

这与"AC bias 要求静态源"的求解器契约不一致。

**建议：**

-   不要让 `source_clock()` 同时承担时钟管理和时变源分类。
-   为模型提供独立的 AC 适用性声明。
-   优先采用显式白名单：只有明确满足 AC 偏置条件的模型才能进入 AC 分析。
-   对 Audio、Impulse 增加必须拒绝 AC 分析的回归测试。
-   新增模型时，要求显式声明 DC/AC/Transient 支持能力。

示意代码（变体需以实际源码为准）：

``` rust
pub fn supports_stationary_ac_bias(&self) -> bool {
    matches!(
        self,
        Self::Resistor { .. }
            | Self::DcVoltageSource { .. }
            | Self::Capacitor { .. }
            | Self::Inductor { .. }
    )
}
```

### 4.2 Newton 修正量容差使用错误的单位分类

**优先级：P1**\
**位置：** `solver/newton.rs`、`topology/mod.rs`。

前轮检查发现，Newton 修正量归一化逻辑根据未知量下标区分电压与电流：

``` rust
if i < layout.node_count {
    VOLT_TOL
} else {
    AMP_TOL
}
```

但 `Layout::compile()`
中节点电压之后的未知量并不全部是电流，还可能包括模型内部状态。

  未知量                   实际单位
  ------------------------ ----------
  节点电压                 V
  支路/端口电流            A
  ThermalResistor 温升     K
  Regulator 检测电压平方   V²

因此，将所有非节点未知量统一按电流容差处理不正确。

可能后果：

-   温升修正量被错误地使用电流绝对容差。
-   V² 内部变量也被错误地使用电流绝对容差。
-   修正量范数与物理变量尺度不匹配。
-   即使残差已满足要求，也可能继续迭代或耗尽 Newton 迭代预算。
-   重复使用同一分类逻辑的 `resolved_increment` 判据也会受到影响。

**建议：**

1.  在 `Layout` 中为每个未知量保存明确的单位/尺度描述。
2.  未知量修正容差与方程残差容差分开定义。
3.  使用无量纲化后的修正量范数。
4.  为每种未知量类型增加独立测试。
5.  覆盖混合电气/热模型和内部状态变量。

示意：

``` rust
enum UnknownUnit {
    Volt,
    Ampere,
    Kelvin,
    VoltSquared,
}

struct UnknownScale {
    unit: UnknownUnit,
    absolute_tolerance: f64,
}
```

实际单位体系应按项目模型扩展，不应只为当前例子硬编码。

### 4.3 稀疏求解器的尺度与主元判据

**优先级：P1/P2**\
**位置：** `native/crates/em-core/src/solver/sparse.rs`。

前轮检查发现当前实现做了行均衡，未看到对应的列尺度处理，主元判定使用固定浮点阈值：

``` rust
if diagonal.abs() <= 64.0 * f64::EPSILON {
    return Err(rejected(
        "Singular or ill-conditioned system: dependent branch constraints",
    ));
}
```

行均衡后，矩阵仍可能因变量列尺度差异而病态。MNA
系统还可能混合电压、电流及内部状态变量。

例如电容等效导纳：

\[ G_C = `\frac{C}{h}`{=tex} \]

当时间步长 (h) 很小时，等效导纳可能变得很大，导致矩阵尺度差异扩大。

需要区分真正的奇异矩阵、数值病态但仍可能求解的矩阵，以及因尺度不佳而难以稳定求解的矩阵。

**建议：**

-   引入未知量尺度变换或列均衡。
-   使用相对主元判据，并结合矩阵尺度。
-   改善奇异与病态的诊断区分。
-   增加不同时间步、不同元件参数数量级下的矩阵测试。
-   评估条件数估计或其他病态程度指标。
-   不要单纯降低固定阈值来"修复"问题，以免接受不可靠解。

### 4.4 保护事件定位的误差处理不一致

**优先级：P1/P2**\
**位置：**
`native/crates/em-core/src/session/circuit.rs`，前轮记录指向第 553--660
行附近。

正常推进阶段，误差超限时可以缩小时间步并重试；保护事件定位阶段，如果某次试探误差超限，则可能直接返回
`Partial`。

可能后果：

-   正常推进可以通过缩小步长成功。
-   保护事件已被发现。
-   事件定位中的某个试探步误差超限。
-   整个 Advance 被中断，而不是继续细化定位。

**建议：**

-   让事件定位也具备受控的步长缩减/重试策略，或采用明确的误差控制事件定位算法。
-   保留事件时间的上下界，避免重试过程中丢失定位区间。
-   测试事件发生在步长内部、接近步长端点及多个事件接近发生的情况。
-   明确 Partial 的状态语义：哪些状态已接受、哪些事件尚未提交。

## 5. 数值算法与物理模型风险

以下事项在前轮审查中被列为需要验证的风险，不应在没有进一步实验的情况下直接认定为数学错误。

### 5.1 时间与相位语义

**位置：** `solver/transient.rs` 与时间相关模型。

不同模型可能通过绝对时间或独立 `source_phases`
取得时间信息。该设计可以成立，但需要统一定义时间语义和相位权威来源。

重点测试：

-   连续推进大量小步。
-   一次推进较长时间。
-   同一时间区间采用不同子步数量。
-   中途修改参数。
-   Snapshot 保存与恢复。
-   负频率机械源。
-   不同源的相位是否保持独立且连续。

相位比较应采用圆周距离，而不是直接比较角度浮点数：

\[ d(`\phi`{=tex}\_1,`\phi`{=tex}\_2)=
`\left`{=tex}\|`\operatorname{atan2}`{=tex}
(`\sin`{=tex}(`\phi`{=tex}\_1-`\phi`{=tex}\_2),`\cos`{=tex}(`\phi`{=tex}\_1-`\phi`{=tex}\_2))`\right`{=tex}\|
\]

建议明确统一的求值上下文，至少包含物理时间与各时钟相位。

### 5.2 Newton 线搜索与尺度

**位置：** `solver/newton.rs`。

当前线搜索使用当前迭代点计算的残差尺度评估试探点。这具有尺度固定、便于比较的优点，但强非线性模型中，当前点与试探点的局部尺度可能差异较大。

重点验证大温升、半导体工作区边界、强耦合、极低/高电流及参数接近模型边界等情况。

建议先修复未知量容差问题，再重新评估线搜索。不要简单地让每个试探点自行改变
merit function 的尺度，否则不同试探点之间的下降比较可能失去一致性。

### 5.3 Backward Euler 与能量核算

**位置：** `solver/transient.rs`、`session`、`model`。

当前瞬态方案使用 Backward Euler：

\[ F(x\_{n+1})+ `\frac{Q(x_{n+1})-Q(x_n)}{h}`{=tex}=0 \]

该方法适合稳健的一阶瞬态推进，但数值阻尼会影响能量表现。

需要区分物理元件的真实耗散、Backward Euler
引入的数值耗散，以及状态提交或回滚造成的能量账本变化。

建议在 RC、RL、RLC 基准电路上建立能量平衡测试，并单独量化数值积分误差。

### 5.4 变压器与互感模型

**位置：** `model/windings.rs`。

当前互感矩阵形式：

\[
```{=tex}
\begin{bmatrix}
\lambda_p\\
\lambda_s
\end{bmatrix}
```
=
```{=tex}
\begin{bmatrix}
L_p&M\\
M&L_s
\end{bmatrix}
\begin{bmatrix}
i_p\\
i_s
\end{bmatrix}
```
\]

需要验证空载励磁电流、短路漏感行为、同名端极性、两侧铜损独立性、接近完全耦合时的数值稳定性，以及极端变比下的尺度问题。

正定条件：

\[ L_pL_s-M\^2\>0 \]

应继续保留，但要验证合法参数在浮点误差下不会被误拒绝。

### 5.5 热模型

**位置：** `model/thermal.rs`。

当前热模型采用：

\[ C\_{`\mathrm{th}`{=tex}}`\frac{d\theta}{dt}`{=tex} =
P\_{`\mathrm{electrical}`{=tex}}-G\_{`\mathrm{th}`{=tex}}`\theta`{=tex}
\]

以及：

\[ E\_{`\mathrm{thermal}`{=tex}}=C\_{`\mathrm{th}`{=tex}}`\theta`{=tex}
\]

需要重点验证热储能、热耗散和电气功率输入的能量闭合。

前轮还发现 `ThermalResistor`
的温度系数参数限制为非负。这限制了模型对负温度系数材料的表达能力，属于当前模型范围限制，不应直接视为实现错误。

### 5.6 BJT/MOSFET 模型

**位置：** `model/bipolar.rs`、`model/mosfet.rs`、`model/element.rs`。

建议验证截止区、线性区、饱和区、工作区边界、反向偏置、极低/高电流、温度变化、动态电荷和电容，以及解析
Jacobian 与数值微分的一致性。

## 6. Java/Rust 集成与工程问题

### 6.1 Java 设备适配与 Rust 实际能力需要建立映射

**优先级：P1**

前轮检查指出，Java 侧已有较多设备适配器，但 Rust FFI
能力声明中存在"isolated circuit harness only; no world simulation
capability"的限制性说明。

因此，Java 中存在适配类不代表 Rust 内核已经实现相应物理能力。

建议建立设备能力矩阵：

  能力               Java 适配    Rust 模型        求解器支持        端到端测试
  ------------------ ------------ ---------------- ----------------- ------------
  RLC                待逐项核对   已有基础模型     DC/AC/Transient   待核对
  BJT                有相关适配   已有模型         待逐项核对        待核对
  MOSFET             有相关适配   已有模型         待逐项核对        待核对
  热模型             有相关适配   已有模型         待逐项核对        待核对
  无线电             有适配       有音频相关模型   待核对            待核对
  电机               有适配       待核对具体模型   待核对            待核对
  铁路供电           有适配       待核对具体模型   待核对            待核对
  世界级多设备联动   有协调层     完整覆盖未确认   待核对            待核对

"待核对"不是判定不支持，而是提醒不能从 Java 接口存在推断 Rust 已实现。

### 6.2 `CeeNativeWorld` 职责集中

**优先级：P2**

前轮记录：

-   `CeeNativeWorld.java` 约 945 行。
-   `SimulationCoordinator.java` 约 325 行。

`CeeNativeWorld`
涉及世界读取、设备识别、端口映射、拓扑生成、波形捕获、模拟生命周期、NBT
恢复和世界副作用提交等职责。

建议保留 `CeeNativeWorld` 作为 Facade，将具体职责拆分到：

``` text
CeeNativeWorld
 ├── WorldCapture
 ├── DeviceRegistry
 ├── TopologyCompiler
 ├── WorldSnapshot
 ├── WorldEffectApplier
 ├── DeviceIdentityManager
 └── SimulationLifecycle
```

拆分目标是降低职责耦合，不是机械地拆小文件。应保留现有线程所有权和状态事务语义。

### 6.3 协议版本与模组版本耦合

**优先级：P2**

前轮检查指出协议兼容性主要依赖 `MOD_VERSION`。这会使模组版本与 Java/Rust
通信协议演进耦合。

建议协议头独立包含：

``` text
ProtocolHeader
 ├── magic
 ├── protocol_major
 ├── protocol_minor
 ├── feature_flags
 ├── payload_length
 └── request_id
```

这样可以分别管理不兼容协议变更、向后兼容扩展、能力协商、请求关联与诊断。

现有协议的 Little-endian、长度限制、NaN/Infinity
检查、截断检测和尾随字节检查等防御性设计值得保留。

### 6.4 构建与发布流程无法从上传包复现

**优先级：P0**

前轮检查记录指出，上传包缺少完整 Gradle/workspace 配置，Rust crate 使用
workspace 继承字段，`em-protocol/build.rs` 还读取 `gradle.properties`
中的版本信息。

因此，不能仅凭该压缩包确认：

-   Rust workspace 是否可编译。
-   Java 与 JNI ABI 是否匹配。
-   各目标平台 native 库是否正确打包。
-   自动化测试是否在 CI 中执行。
-   最终模组是否可以从干净环境完整构建。

这可能只是打包时排除了工程配置，不代表原仓库一定有缺陷。

建议在完整仓库中建立可复现流水线：

``` text
Gradle 配置检查
    ↓
Rust workspace 编译与测试
    ↓
JNI/协议测试
    ↓
Java 验证
    ↓
目标平台 native 打包
    ↓
完整模组构建
```

### 7.2 Jacobian 自动差分测试

建议将它作为所有新设备进入 Rust 内核的准入条件。

对模型残差：

\[ J\_{ij}=`\frac{\partial F_i}{\partial x_j}`{=tex} \]

使用中心差分近似：

\[ J\_{ij}\^{FD}= `\frac{F_i(x+\epsilon e_j)-F_i(x-\epsilon e_j)}`{=tex}
{2`\epsilon`{=tex}} \]

比较解析 Jacobian 与数值
Jacobian。测试应覆盖不同工作区间，而不是只选择一个典型点。差分步长应考虑变量尺度，避免固定绝对步长造成误判。

### 7.3 随机小型电路性质测试

建议建立随机电路生成器，生成小规模合法拓扑，并执行

随机测试必须保证生成器输出合法输入，并记录随机种子，以便复现失败样例。

## 10. 最终结论

Create-Electromagnetism
的整体架构方向值得保留。当前最需要解决的不是"还能添加多少设备"，而是证明已有设备在复杂拓扑、非线性工作区间、长时间运行、状态恢复和异常提交下仍然满足正确性要求。

最明确的修复重点：

1.  AC 时变源识别。
2.  Newton 未知量单位与容差。
3.  Jacobian 自动差分测试。

最值得投入验证工作的部分：

1.  稀疏矩阵病态处理。
2.  瞬态事件定位。
3.  能量守恒与状态事务。
4.  半导体、变压器和热模型的物理边界。

**最终建议：保留架构，暂停盲目扩展设备，以数值正确性和可复现验证作为下一阶段的主线。**
